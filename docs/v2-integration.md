# P0.8 camera + P0.9 declared port inventory

## Integrated camera
Build and flash both `eitek-master` and `esp32-slave` from the same revision. Default outputs and RS485 remain disabled. Do not connect real load power during commissioning. The camera-only build remains available. No extra MCU is needed.

Slave UART: `capture 123` or `python tools/capture_camera.py --port COM5 --out sample.jpg` with actual port, Serial Monitor closed. On the master, with RS485 validated and enabled, send `stop`, wait for remote state 0, then `capture`; the slave exports CAM BEGIN/DATA/END on its UART using the announced sequence ID. To collect a master-triggered frame use a UART receiver already listening on the slave (the local Python script issues its own request, so do not run both requests together). Use 320x240 MJPEG 15 FPS as a starting mode, 55 KiB limit. Enumeration/capture timeout 8 s after successful driver start; export timeout 25 s. Driver setup/teardown can take additional time. Capture acceptance does not mean a frame was saved.

No UVC host starts while slave armed. Camera busy state 3 blocks ARM and dosing. STOP cancels pending session; capture ends only after successful host teardown. Ambiguous start/stop failure retains buffers and latches state 4: reboot with loads disconnected. UART sends at most one chunk per loop, after USB host has stopped. Master disarmed capture only; master disarms local outputs on link loss. Test capture while armed (must reject), ARM while queued/receiving/exporting/fault (must reject), repeated capture, disconnect, STOP, no camera, reboot and actual OFF deadlines with oscilloscope/dummy loads. The driver may block while disarmed; do not treat this as hard real-time safety certification. Do not run camera and pumping simultaneously in this bench milestone. No exposure/white balance control, light coordination or automatic assay capture yet.

## Port inventory
Each board emits an `INVENTORY {JSON}` line at boot or when asked while disarmed. It identifies board, role, stable eFuse hardwareId (not credential), schemaVersion 1, revision 2, compile-time enable flags and declared ports. Fields: portId, kind, direction, channel, gpio (null for external ADC), optional gpio2 (RS485 TX/RX or USB D-/D+), assigned, discovery=declared, remoteControl=false. The EITEK manifest includes eight relay outputs, eight DI inputs (unassigned), four ADC channels, RS485. Slave includes eight MOSFET outputs, PT100, RS485 and UVC. OUT6/CH8 marked reserve. PT100 gpio is SPI CS only; see wiring docs for bus pins. Assigned is intended wiring, not electrical detection. No physical sensor/device presence is asserted. Output GPIO mapping shared with control code. Bump revision on descriptor changes; do not use it as a persistent provisioned inventory revision until Kiosk contract is integrated.

Old PR #1 reported the legacy NO2 board pins through a network reporter. Its declared-inventory idea is migrated here; do not merge the legacy code. No network reporter or backend port registration in this PR. Follow-up must validate current Kiosk manifest API, provisioned device identity, auth, transport and revision persistence before automatically syncing. Do not invent attached devices from manifest.

## T10 legacy isolation gate
The root legacy sketch is intentionally non-buildable, with an unconditional compile error before any Arduino code. Keep historical sources for reference; no legacy reporter, automatic port discovery or network control is migrated. Default CI builds exactly the V2 master, slave and camera-only targets, verifies source filters and rejects enabled output/RS485/assay build flags, and checks the default disabling definitions. No flash, GPIO or protocol runtime change. Physical reset, wiring and stop behavior remain P3 acceptance.
